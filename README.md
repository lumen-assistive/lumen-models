# lumen-models

[Italiano](README.it.md) | English

Model conversion, quantization, and benchmark scripts for
[Lumen](https://github.com/lumen-assistive), plus the project's model
and dataset license ledger.

## What this is

- `docs/LICENSES.md` / `docs/licenses.yaml`: the human-readable and
  machine-readable license ledger for every model, inference engine,
  and symbol set considered for Lumen, including flagged conflicts
  (Ultralytics YOLO's AGPL-3.0, Piper's relicensing from MIT to
  GPL-3.0, ARASAAC's non-commercial clause) and how each is handled.
  **Read this first** if you are adding any new model.
- `src/lumen_models/catalog.py`: the `ModelDescriptor` catalog, mirroring
  the shape of `lumen_sdk`'s `ModelDescriptor` contract. Empty today;
  entries are added only once a real on-device artifact exists.
- `src/lumen_models/license_check.py`: an automated compliance gate —
  CI fails if a catalog entry ever references a license that is
  missing from the ledger or not cleared for Apache-2.0 distribution.
- `src/lumen_models/convert/`: the model conversion pipeline interface
  (`ModelConverter`), with a reference `CopyConverter` implementation
  exercising the manifest/checksum shape every future per-framework
  converter (TFLite, ONNX, GGUF) will follow.
- `src/lumen_models/benchmark/`: a benchmark harness measuring wall-clock
  latency and process memory for a caller-supplied inference callable.
- `docs/benchmarks.md`: the (currently empty) published benchmark
  table; generated by `lumen-models render-benchmarks`, never hand-edited.

## Current scope

No model has actually been converted, quantized, or benchmarked yet.
This release ships the governance and tooling scaffold — the license
ledger, the catalog schema and its compliance gate, the conversion
pipeline interface, and the benchmark harness — all real and tested.
Per-framework converters (TFLite, ONNX, GGUF for whisper.cpp/llama.cpp)
are added incrementally as each plugin module needs a concrete model,
rather than installing several heavyweight ML toolchains speculatively
ahead of need.

## Development

```
python -m venv .venv
.venv/Scripts/activate  # or source .venv/bin/activate on Linux/macOS
pip install -e .[dev]
ruff check .
ruff format --check .
mypy .
pytest --cov
```

Install the shared commit message hook before committing:

```
git config core.hooksPath .githooks
```

See [CONTRIBUTING.md](CONTRIBUTING.md) for the full workflow, including
how to add a new model to the catalog without breaking the license gate.
